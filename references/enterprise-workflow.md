# 企业双源执行与恢复

此文档仅描述API模式。用户禁止付费或明确要求已登录网页时，改读 `browser-enterprise.md`，不运行本文双源验证及执行命令。

## 输入与权限

不重新采集淘宝，不扩大用户名单。优先读取独立平台资质，然后是已确认的主体映射。名单由Agent灵活归一化为 `input_shops.json`，每行保留店铺名、链接、原始来源和已提供公司；无需让用户制作固定模板。

`enterprise_pipeline.py` 的默认行为只规划，不访问企业接口、不创建结果文件。真实执行前，两私有源必须验证成功；只发现安装文件不算就绪。配置缺失时使用现有配置助手，不能把Key放在命令参数里。

```powershell
python scripts/enterprise_pipeline.py --mode paid-api --job-dir <绝对任务目录> --limit 1
python scripts/enterprise_pipeline.py --mode paid-api --allow-paid-api --job-dir <绝对任务目录> --limit 1 --execute
python scripts/enterprise_pipeline.py --mode paid-api --allow-paid-api --job-dir <绝对任务目录> --limit 10 --execute
```

以上执行命令只在用户重新明确授权付费API时使用；预检另需 `preflight.py --allow-paid-api` 或 `bootstrap.ps1 -AllowPaidApi`。先验证1条，再按已授权范围验证10条及恢复，不机械要求重复确认。以上不授权外部上传、发消息或修改商家资料；超范围扩展和前台操作另行确认。

## 路由与来源

- 精确主体先企查查工商核验，再检索风鸟精确同名候选、按内部ID核验基本信息；双源身份一致后才取企查查联系方式。
- 模糊店铺/品牌先风鸟发现，保留最多5条服务端候选与“非穷尽”口径，分别做精确工商核验，不自动选择第一条。
- 两源企业名/信用代码冲突立即暂停。地址、法人等非身份字段冲突保留双方原值和来源，企查查已有值不被静默覆盖。
- 风鸟只补其真实提供的基本工商字段；当前基础工具不支持电话/邮箱查询。联系方式缺失就保留缺失，不能借另一企业的电话拼齐。
- 双源核验通过不等于店铺关系已确认。平台执照来自独立资质文件；其他候选只有信用代码闭环且有来源才可 `selected: true`。
- 成品同时保留原关联证据、`source_url` 和 `sources[].url`，去重后写入主体核验及正式表的数据来源列；服务商入口链接只说明企业数据来源，不能当作店铺主体闭环证据。

## 缓存与审计

- `enterprise_calls.json`：按来源、工具与完整查询参数的哈希缓存成功响应，默认24小时；保留时间、失败状态和工具来源，不存凭证。失败响应不得命中成功缓存。
- `enterprise_checkpoint.json`：保存计划哈希、每店指纹、已完成/待处理对象、暂停原因和实际接口调用数/缓存命中数；该计数不包含两源就绪探测。
- `company_candidates.json`：模糊发现原始候选及截断口径。
- `company_enrichment.json`：企业登记、联系方式、补缺字段来源、冲突值和候选主体关系；`entid` 仅内部使用，不进入成品表。
- 同一公司可共享工商查询，但不能共享不同店铺的 `selected`、证据或授权关系。每次重跑都会从当前输入重新合并主体关系。
- 旧 `enrich_companies.py` 的企业缓存分别以工商7天、联系方式24小时失效；保留作为低层兼容工具，新业务任务统一使用双源编排。

## 停止与恢复

任一源鉴权、额度、数据结构或身份检查失败即暂停，不切换账号、不自动单源降级。查看检查点的脱敏原因，修复后重跑同一命令；成功且新鲜的查询跳过，失败步骤重新执行。空候选保留商家并记为 `not_found`，不是淘汰。

企查查明确说明“已全量扫描该主体联系方式数据库，未发现任何记录。”属于已成功查询但未披露联系方式，标准化为 `contact_status: not_disclosed`，商家继续保留；未知结构仍须暂停。这一路径已用真实返回复现，并有回归测试。更换结构不得通过手改缓存绕过校验。

企查查的SSE响应可能不声明charset，预检和查询均按UTF-8解码再解析。不能只凭HTTP 200判定可用，也不能让默认Latin-1解码把中文说明中的字节误识别成换行。预检必须取得合法MCP工具列表；无法解析时停止，不降级为“已就绪”。

新增或修改资质/主体后计划指纹变化；缓存仅共享相同查询，身份结论重新计算。不得修改缓存中的失败状态冒充成功。

回滚前保存源码、安装版和任务输入；新输出/检查点与旧数据分开存放。旧代码不得读取不支持的新检查点格式。安装版同步只覆盖基线一致的文件，有双方修改时停下做三方合并，不覆盖本地独有文件。

## 验证

先运行 `python -B -m unittest discover -s tests -v`。真实验证使用新的隔离任务目录，保留用户原名单与历史数据。记录1条/10条的耗时、接口调用量、主体一致性、失败恢复与重跑命中；没有真实执行就只报告离线验证。
