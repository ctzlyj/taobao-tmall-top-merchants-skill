# 审核筛选模式

## 适用场景

当用户提供已有店铺行的审核工作簿，并要求核验“是否符合引入画像”和“引入优先级”时使用本模式。它与用户指定名单模式独立：指定名单模式不打开淘宝、不推断 SPU；审核筛选模式必须访问店铺公开页面并保存证据。

## 环境检查

运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/bootstrap.ps1 -AuditOnly
```

本模式不要求企查查 Key，也不要求风鸟 Key，不调用企业主体查询。它仍要求 Python、依赖、Chrome、o2、webcli、Browser Bridge 和淘宝登录态正常。

## 默认选行

- 自动识别店铺名、审核结论、引入优先级、负责人、店铺链接、类目和电话等语义列，不依赖固定列号。
- 只处理当前负责人名下、店铺名非空、两个审核结果均为空的行。
- 已完成结果优先复用；只补充新店时仅访问新店。
- 同店同类目重复行共享结论，但保留并回填所有重复源行；同店跨类目分别审核。检查点还绑定规则指纹和采集时间，超过24小时不复用。
- 空白占位行和合并单元格从属行保持空白。

## 审核证据

- 相关 SPU 按唯一商品 ID 去重，页面卡片数量和分页总数不能代替 SPU。
- 高销链接只认公开页面上的“人付款”“已售”或“总销量”展示下限，达到 10000 才计数。
- 高：相关 SPU 至少 20 且高销链接至少 3；中：未达高但相关 SPU 至少 15 且高销链接至少 1；其余为低。
- 页面故障、类目边界不清、未知销量或证据不足写“待核验”，不得判低。首页出现少量商品不代表全店只有这些商品；高门槛已被观察证据证明时可提前结束，低结论必须有完整覆盖和可观测销量证据。
- 主图能力写“主图能力待人工确认”；无明确 KA 名单写“非KA待业务复核”；销量仅作为付费/毛利规模代理。

## 浏览器流程

默认通过 o2、webcli 和 Browser Bridge 复用日常 Chrome。店铺严格串行，相邻实际访问等待随机 18–22 秒。

页面顺序：店铺首页 → 同源 `/search.htm?search=y&orderType=hotsell_desc` → 淘宝公开店铺列表页。每一级保存最终 URL 和证据来源。

长 `click.simba.taobao.com` 链接不得拼入 shell 命令。先打开淘宝受控标签页，再用序列化参数调用 `location.assign`。

登录失效、验证码、滑块、隐藏 `_____tmd__` iframe、Bridge 断连或页面不兼容时，立即保存检查点并暂停。不得绕过、换号、判低或从头高频重跑。

## 运行与恢复

先检查任务：

```powershell
python scripts/review_workbook.py "审核筛选.xlsx" --output "审核筛选_已完成.xlsx" --owner "负责人" --dry-run
```

确认后执行：

```powershell
python scripts/review_workbook.py "审核筛选.xlsx" --output "审核筛选_已完成.xlsx" --owner "负责人"
```

默认检查点与输出文件同目录、同名并使用 `.review-checkpoint.json` 后缀。故障解除后重跑相同命令，只复用同店、同类目、同规则且24小时内完成的结论。旧v1数据先备份为 `.v1.bak`，再迁移为v2，不覆盖原证据。

## 输出保护

原工作簿只读，输出路径必须不同。除两个审核列和必要的手机号文本显示格式外，不修改其他单元格；公式、超链接、样式、行列尺寸、冻结窗格、筛选、合并、工作表顺序和重复行均需保留。
