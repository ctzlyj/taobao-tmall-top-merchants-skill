# 爱企查网页补查

## 定位与边界

入口：[爱企查移动网页](https://m.aiqicha.com/)。作为风鸟、企查查之外的公开企业联系方式补查渠道，也响应用户指定优先使用爱企查的请求。不调用付费API，不安装或启用爱企查MCP，不因企业API额度不足申请新Key、预检额度或自动开通会员。

先读全局 `browser-task-router` 并按需加载工具指南，优先复用已有授权浏览器、任务专属后台页。网页实际要求登录时核实会话权限；不复制Cookie、Token、个人Profile，不切换或导航工作标签页。收到域名跳转时核验实际站点；只跟随可见链接，不猜搜索接口、详情路由、企业ID或凭证参数。

当前执行方式为Agent按实时页面观察及核验，不是已验收的爱企查自动搜索/详情接口。`browser_targets.json` 与 `browser_enterprise.py` 仍是风鸟专用路径，不能把爱企查详情链接填入以绕过校验；不为了加入一个来源放宽风鸟域名限制。

## 可访问时的流程

1. 在用户给出的企业范围内按完整企业名或已提供信用代码搜索。仅店名时先补平台经营主体证据；搜索结果只作候选，不取第一条或按相似名称认定。
2. 从搜索卡片取得实际详情URL，核对完整企业名及统一社会信用代码/工商注册号。15位工商注册号不是18位信用代码；同名、分公司、曾用名不能代替当前主体。
3. 只读取企业详情及可见联系方式区域。正常可见且无需付费的展开可用；拨号、发消息、报告导出、会员解锁不属于只读查询。不得收集页面页脚的爱企查客服或已登录账号电话。
4. 逐号码保留原文、来源URL和读取时间；只在页面明确对应号码与联系人/职务时记录该映射。只有法人字段时，联系人为“未披露/未确认”，不要用法人、股东、邮箱昵称推断号码使用人。
5. 与已有渠道交叉核验：先企业身份，再电话/邮箱。保留全部去重的公开号码和各自来源；人员冲突写“来源冲突，暂停认定”，不按新旧或出现频次自动选人。来源明确标注仍须写“未拨通”。
6. 保存后独立回读本地记录，逐项检查公司、号码、缺失与受限状态；不把用户截图写成Agent已访问的网页。用户提供的截图可作为人工证据，来源类型和采集时间不明项必须注明，不能伪造实时访问时间。

## 状态与停止

| 状态 | 判定与后续 |
| --- | --- |
| `visible_records` / `visible_records_partial` | 已看到企业公开联系方式；更多未读取或有遮罩时不声明全量 |
| `not_disclosed` | 仅限正确企业详情在已核验身份后明确显示无记录；不是企业没有联系方式的绝对结论 |
| `masked` | 网页号码遮罩，不补全、不以其他来源号码反推解锁 |
| `auth_required` / `challenge_required` / `rate_limited` | 登录、验证码、频控导致本来源未完成；保留已有结果，说明具体阻塞 |
| `paid_access_required` | 要求购买/积分/会员解锁时停止该功能，不自动使用API或其他收费服务 |
| `access_blocked` | 当前访问方式被限制，例如“请关闭浏览器的调试窗口再访问页面”；停止当前连接，区分调试兼容问题与登录/权限门禁，不直接判定所有工具不可用 |
| `page_not_ready` / `structure_unknown` | 空白、未加载或结构未知，不能标成 `not_disclosed`；允许有界诊断，无界重试不可用 |
| `not_queried` | 站点入口已受限，目标企业尚未查到详情；不能把计划查询计为已查询 |

仅有调试窗口提示时，允许有界诊断工具兼容性：先释放任务页的调试连接，再选不附加调试协议的正常访问方式；工具名称不同不代表底层不同。BrowserSkill也使用调试协议，重复更换同类控制器不能证明已换路径。不得注入关闭检测代码、改浏览器指纹或读取隐藏初始化数据来绕过页面限制。

已实测的无调试连接路径是本机正常安装Chrome的原生 `--headless --dump-dom`，不传调试端口、不接CDP，使用任务专属空Profile并限制进程运行时间；不复制个人Profile或凭证，不干扰工作窗口。此路径只证明公开首页可读，不继承用户登录，也不是已验收的企业搜索/详情适配器。搜索地址必须来自站点实际导航证据，不能猜测接口。首页成功后仍需分别验证搜索、详情及企业身份。

出现登录、验证码、权限或付费门禁后，不更换工具、账号或端点绕过，停止该受限步骤，不批量重放余下企业；允许继续其他原本可访问的独立公开来源，但必须标明不是爱企查验证。确需人工操作时只提出必要登录或安全验证，不默认要求用户整理企业截图或选择工具。需要可见验证窗口时先征得用户同意，保留同一任务会话并在完成后重新核验；会话已关闭或Profile已删除时必须说明需要新建，不能承诺验证一次就必定可完成查询。用户主动提供截图时按人工证据接收，不请求登录凭证，不占用工作窗口。

HTTP 200、标题出现“爱企查”、已安装浏览器工具或拿到首页HTML，均不代表已拿到企业详情/联系人。未完成真实企业详情身份核验与字段回读，不能宣称自动查询已打通。

## 证据交接

在任务目录保存 `aiqicha_observations.json`，不覆盖此前商家结果；恢复诊断另存回执并指向前次记录。每个目标记录 `shop_name`、`company`、强身份字段、`source: aiqicha_web`、`status`、已观察的 `source_url`、`captured_at` 和 `evidence_type`（例如 `agent_observed_webpage` / `user_provided_screenshot`）。企业尚未尝试查询时用 `status: not_queried`，另记实际 `site_status` 与站点提示；已尝试搜索但被验证码拦截则用 `challenge_required`，企业详情完成数仍为0，其他目标不能计为已查询。区分首页可读、搜索尝试、详情完成和新号码数；不得补造详情URL、号码、法人或查询成功状态。缺少原始观察时刻时留空，只记已知日期及回执保存时间。

确实读取到的联系方式用 `phones`、`emails` 和最小范围原文 `excerpt` 保存。没有完整号码时保留原始遮罩文字，不新增可拨电话。仅对来源明确标注的“号码—联系人”生成 `contact_evidence`：`phone`、`person`、`role`、`company`、实际详情URL `source_url`、有依据的 `captured_at`、对应原文 `excerpt`、`association: explicit`；多号多人逐个处理。

复用 `browser_contacts.contact_rows(record, contact_evidence)` 完成逐号码称呼与冲突处理。它处理的是已核验的证据，不会搜索爱企查，也不能证明输入证据来自实时网页；生成“explicit”前必须观察到实际对应关系。用它处理新增爱企查号码前，Agent负责完成企业身份核验，不用它替代网页取数或主体校验。

## 验证与维护

2026-09-20复测：WebCLI后台页曾变为空白，附加调试协议的浏览器及BrowserSkill出现调试窗口提示；改用正常安装Chrome的原生无调试连接模式后，公开首页可读。同一任务Profile随后执行站点导航提供的企业搜索，出现“百度安全验证”“请完成下方验证后继续操作”，未取得企业详情或新电话，停止后续目标；临时Profile已清理。根因分两层：调试连接兼容问题已有首页级解决路径，企业搜索仍有安全验证门禁。不能将前者扩大为全部工具不可用，也不能把后者写成未披露。

运行 `python -X utf8 -B -m unittest discover -s tests -p test_aiqicha_web.py -v` 验证来源路由、受限状态、既有联系人证据兼容、冲突与凭证URL拒绝。测试里的详情地址是合成样例，不是可用于查询的路由模板。以后在正常授权访问恢复时，再逐步现场核验单条搜索、详情、身份、电话和独立回读；仅验证成功的路径才写成站点自动适配器。回退只移除本次来源引用和新增参考文件，不回退为付费API，不删除原有证据。
