# 公开来源电话碎片交叉验证（会员墙免费替代）

触发条件：目标企业的联系方式在某一平台（如企查查）明确显示有电话，但被会员/付费墙挡住。**受限不等于未披露**——同一工商年报电话依法公示，常被多个免费公开来源以不同遮罩转发。本流程只使用其他免费公开来源，不绕过受限平台的会员墙、验证码或账号门槛。

## 固定流程

1. **锁定身份**：先从任一可访问来源拿到企业全称+统一社会信用代码。企查查详情页头部信息对无头浏览器会跳 405，用任务专属有头浏览器会话可读页面标题与头部；直接 HTTP 请求会被 JS 反爬，不硬抓、不重放。
2. **逐个免费来源找同年报电话的不同遮罩**（有头浏览器任务会话，保持访问节奏）：
   - 百度搜索企业全称：结果中的爱企查聚合卡展示打码电话（挡后4位，如 `1586219****`）及逐年 `phoneinfo`（2025年报/2022年报/2020年报等）；百度百科/百度AI聚合内容可能直接给出全号，按候选全号处理。
   - 爱企查详情页 HTML：`telephone`/`phoneinfo` 字段，挡后4位；跨年不同号码是不同年报记录，不算冲突。
   - 黄页站（如 yellowurl.cn，百度结果中常以小写信用代码为子域，如 `9132032159558848xl.yellowurl.cn`）：挡前4位，如 `****2198552`。
   - 邮箱前缀若为11位手机号（如 `15252112888@qq.com`），记为"邮箱前缀线索"，不是核实电话。
   - 国家企业信用信息公示系统 gsxt.gov.cn 对自动化强拦截（白屏），优先免费聚合源，不在官网反复消耗。
3. **用 `scripts/public_phone_hunt.py` 做碎片交叉验证**（输入 JSON：company/credit_code/fragments/emails，输出 phones/unresolved/email_hints）：
   - 全号+遮罩碎片（不同源）位置一致，或前缀遮罩+后缀遮罩互补覆盖全部位数 → `cross_validated`；
   - 仅单源全号 → `single_source`，交付时标注"单源未核验"；
   - 碎片不能完整确定的 → 保留原始遮罩原文，**不新增可拨电话**；
   - 排除信用代码/注册号子串误报（如 `9132032159558848XL` 内含 `13203215955` 段）。
4. **交付**：号码+来源清单+验证状态+年报年份标签；百度 HTTP 搜索几轮即触发安全验证，改用有头浏览器会话并限速；单源号码拨通前先核实仍在使用。

## 红线

- 不绕过、不重放、不换账号访问受限平台；只用其他免费公开来源的已公示数据。
- 交叉验证不成立就不拼号；遮罩原文原样保留，来源冲突时暂停认定。
- 号码归属依据写明各来源与遮罩方式；邮箱前缀线索单独标注，不冒充年报电话。
- 公开搜索结果会混入"同名异地"与"相似名"公司串扰（2026-10-08 实测：目标安徽亮鑫返回山东亮鑫/南通亮鑫、目标北京捷夫返回北京鑫艺诚遮阳、目标徐州两脚兽返回徐州金之轩）：证据必须同时核对公司全称+同址/同信用代码才可采信，仅凭号码重复出现次数不采用。
