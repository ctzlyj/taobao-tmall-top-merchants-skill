# 区域产业带走访发现（零付费API）

触发条件：用户给出区域（市/县/镇或产业带）和类目，目标是**线下拜访、邀请入驻**，而不是线上店铺清单。适合"我在某地，帮我找当地做某类目的公司/工厂，最好有品牌"这类请求。

## 固定流程

统一入口 `scripts/local_belt_discovery.py`，四个阶段都要求任务专属后台会话和独立输出目录，不接管用户工作标签页。

1. **collect**：企查查已登录网页检索。`--region 邳州 --keywords 沐浴,泡脚,木梳 --suffixes 制造,电子商务 --session <任务会话> --out-dir <绝对路径>`。每轮打开 `qcc.com/web/search?key=区域+关键词`，8 秒后读取含"统一社会信用代码"的企业卡片；命中"安全验证/访问过于频繁"立即整批停止，不换账号、不重试风控。
2. **parse**：合并多轮结果，按公司名去重、字段互补，按类目词、经营状态、制造痕迹和区域命中打分排序，输出 `companies.json`。排序只是拜访优先级线索，不是准入结论。
3. **verify**：对重点候选逐家风鸟核验。先风鸟精确名称搜索取详情链接，再调用 `webcli riskbird company` 适配器做名称+信用代码身份核验并读取企业公示头部电话/邮箱。
4. **trademarks**：对已核验企业读取风鸟详情页"知识产权"页签，取商标/专利总数和首页已注册商标明细，用于"有品牌商标优先"排序。`--session <任务会话> --out-dir <绝对路径> --ip-file riskbird_ip.json`，导航间隔同样 ≥20 秒。
5. **contact-fallback**：联系方式获取优先级是**浏览器自动化 → 免费公开来源碎片交叉验证 → API 兜底**。浏览器路径拿不到电话的企业（风鸟未收录/适配器失败/核验通过但电话未披露）先按 `references/public-phone-hunt.md` 找其他免费公开来源的遮罩碎片并用 `scripts/public_phone_hunt.py` 交叉验证（成立得号、不成立保留遮罩），仍无结果才允许付费 API；已拿到电话的企业绝不重复消耗 API。运行 `--out-dir <绝对路径> --allow-paid-api --config <MCP配置>`，复用企查查 MCP `get_contact_info`（风鸟 basic API 不含电话/邮箱，兜底只能用企查查联系方式接口）。`--allow-paid-api` 是花费闸门：用户已在任务中给出"查不到再用 API"的授权时直接携带该参数执行，无需再次向用户确认；输出 `api_contact_fallback.json`，幂等可续跑。

## API 兜底的交付规则

- 兜底结果必须单独标注来源"企查查API兜底"（黄色），不得混入"风鸟核验"（绿色）。
- API 返回的企业名称与目标不一致时保留 `api_identity_conflict`，不取电话、不标记可用。
- API 明确返回"已全量扫描未发现记录"时按 `not_disclosed` 交付，保留该企业但电话写未披露。
- 兜底文件按公司名幂等：已保存的企业不再发起付费调用；失败中断后重跑只补缺失项。
- 2026-10-04 实测：扬州任务对风鸟未收录且无电话的"创新木梳工艺制品厂"真实发起了兜底调用，本机 `~/.codex/config.toml` 未配置 `qcc-company` MCP（报 `qcc-company MCP is not configured`），兜底如实受阻，该企业以企查查底册数据出表并注明；配置好 MCP 后无需改代码即可重试。路由选择、身份冲突、未披露、幂等另有单元测试覆盖。

## 风鸟详情 URL 规则（实测必守）

风鸟搜索结果链接自带 `fuzzyId`、`position` 等跟踪参数，适配器只接受**仅含 `entid`** 的详情 URL，否则返回 `INVALID_REQUEST`。`browser_contacts.riskbird_detail_url()` 负责剥离跟踪参数，`browser_enterprise.normalize_target` 已接入；任务局部脚本也必须先剥离再调用适配器。不得推测内部 ID，不得选第一条模糊结果。

## 身份冲突与联系方式交付

- 适配器返回 `IDENTITY_CONFLICT` 时保留冲突：可按风鸟搜索卡片上的实时信用代码/全称重试一次；仍冲突则该企业联系方式只能标注"风鸟搜索卡片（单源）"，不得标记身份核验通过。
- **必须使用企业全称调适配器**：企查查卡片名可能是简称（如"徐州闽江商贸"，页面全称"徐州闽江商贸有限公司"），简称会误报 `IDENTITY_CONFLICT`；`local_belt_discovery.riskbird_full_name()` 用风鸟卡片链接上的全称替换简称后再核验。
- **冲突先做 registry 级诊断**：用与适配器一致的逻辑读取 `table.xs-descriptions-box` 表格（企业名称/工商注册号/统一社会信用代码/法定代表人）逐项比对。2026-10-03 徐州实测：风鸟把"曾用名：XXX"拼接进企业名称单元格，导致三家真身匹配企业误报冲突；该解析缺陷已在本地适配器修复（比对前剥离"曾用名"后缀）。信用代码、注册号、法人都一致时属于解析差异而非身份不符；名称或信用代码确实不同才保留冲突。
- 企查查卡片上 199/185/138 等疑似虚拟号的号码必须标注"未核验，拨打前注意"；风鸟核验号码标注"风鸟核验"。
- 电话均为企业工商公示电话，页面不标注个人使用人；联系人写"未披露/未确认"，开场建议"您好，我是京东类目招商，想找贵司对接负责人"，先问对接人再称呼，不直呼法人姓名。
- 企业名下两条同名记录（不同信用代码/地址）全部保留并写明冲突，不择一隐藏。

## 拜访清单交付

最终交付 `.xlsx`（用户偏好表格而非长文）：主表含拜访顺序、片区（按拜访路线分组，如产业带→园区→城区→乡镇）、公司名、信用代码、法人、资本、地址、电话、电话来源、邮箱、类目匹配、拜访要点、核验状态；附"使用说明"页写清来源、电话归属、颜色规则（绿=风鸟核验，黄=API兜底或单源冲突，橙=仅企查查卡片未核验）和路线建议。生成后必须用 openpyxl 独立回读行列数与首行内容验收。

## 出差城市排序口径（2026-10-08 用户纠偏）

- **城市目标数不能混用"历史专项存量"与"本轮新发现"**：南京/扬州/徐州数量高是因为此前做过城市专项任务盘全了存量，不是当前最值得去；城市排名必须以本轮全国/城市搜索的无偏新发现为主排序键，历史存量单列参考列，二者在表头分开呈现。
- **"本轮无新发现"≠"该城市没目标"**：新发现为0可能只是本轮搜索词未覆盖（如全国轮没搜泡脚桶/泡澡桶，台州显示0新发现但历史已有8家有效目标）。判断城市是否有目标先查历史台账，勿把搜索词口径当成城市事实。
- **已拜访/未拜访状态先对账再排差旅**：已去过的城市（如南京/扬州/徐州）改电话跟进；历史任务已核验但行程未执行的（如台州/曹县10-09~11计划）仍可纳入新差旅，除非用户明确说已去过。
- 单城单家的强品牌目标（如湖州和也3316商标）不因城市分数低被埋没：单列出"单点王牌"，建议先电话建联再决定是否专程拜访。

## 商标/专利核验（风鸟知识产权页签，零付费）

- 风鸟详情页知识产权数据无需付费：JS 找到 `.info-tabs-item` 中文本以"知识产权"开头的页签，`scrollIntoView` 后原生 `click()`，再读 `document.body.innerText`；用"商标信息/专利信息/作品著作权 + 数字"头取总数。
- 商标表格每行渲染为"序号\t换行\t商标名称\t国际分类\t状态\t注册号\t日期"，解析前先把 `\t\n\t` 归一为 `\t`；`local_belt_discovery.parse_trademark_rows()` 已实现并带测试。
- 只取首页（约10条）：商标大户（如66条）明细不全，总数仍然准确；出表时注明"首页前10条"。
- 招商相关类别优先：第21类（厨房洁具/沐浴洗漱）、第20类（家具/梳）、第35类（广告销售/电商）、第10类（医疗器械/坐浴/刮痧）、第28类（健身器材/筋膜球）、第08类（刮痧板）、第03类（日化）、第11类（汗蒸设备）。
- 风鸟页面头正则会混入平台自身联系方式（18911918041 / contact@riskbird.com），出表电话必须以适配器提取的工商公示电话为准，回读时把平台号码列入黑名单校验。

## 企查查商标搜索与限流边界（2026-10-03 实测）

- 商标搜索 URL：`https://www.qcc.com/web_searchBrand?searchKey=<词>&key=<词>&sbSearchType=0`（综合）/ `sbSearchType=4`（按申请人）。
- 真实按钮是 `button.searchbtn`（外层 DIV 容器点击无效）；JS 直接 click 无效时改用 webcli 原生 fill/click。
- **限流即整批停止**：命中 `verify.qcc.com/limits` 访问限制页时，企查查通道本任务全部停止，不换账号、不重试、不绕过；后续核验全部走风鸟。
- **软限流=空白页**：2026-10-04 扬州实测，企查查限流也可能表现为页面加载完成但 `document.body.innerText` 为空（bodyLength=0、无卡片、无验证码）。连续 3 轮空白页即判定软限流整批停止；`collect_queries(blank_stop=3)` 已实现并带测试。
- **卡片字段串扰**：2026-10-05 南京实测，企查查搜索卡片偶发相邻卡片字段污染（南京木梓日用品的信用码/邮箱/官网被错抓为相邻的南京林业大学，信用码出现 `12` 事业单位前缀、官网为高校域名、法人为"专利"等噪声）。单源卡片字段不直接出表：先用风鸟交叉，信用码/法人/地址不一致时以风鸟为准，并在清单中标注"卡片串扰"；信用码前缀 `12` 是最快的旁证信号。
- **webcli 通道**：部分 Windows 主机上 `o2 launch webcli` 会吞掉 stdout 导致 JSON 解析失败；`local_belt_discovery.webcli_base()` 优先用环境变量 `WEBCLI_MAIN_JS` 指定的入口，其次本机 node 直连 `@jd/webcli/dist/src/main.js`，最后才回退 o2。
- **城市限定词串扰（2026-10-08 实测）**：`"杭州 泡脚桶"` 等城市词会把"宁波杭州湾新区/慈溪/余姚"企业混入杭州结果（"杭州湾"含"杭州"字样），也会召回搜索词弱相关的跨市企业；城市归属必须按地址关键词判定（且"杭州湾"优先归宁波），搜索词只作召回不作归属依据。
- **城市专项搜索配额（2026-10-08 实测）**：企查查城市限定词约连续 20 组后出现全局软限流（杭州 20 组全部有效，随后宁波词连续空白页，冷却 3/10 分钟、换新会话均未恢复）；城市专项一轮控制在 20 词内，风控即停不强撞。
